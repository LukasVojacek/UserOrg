# ADR 0021 - Role-scoped OpenAPI documents are v2-only; legacy User/Administration docs are preserved

- Status: accepted

> Relocated 2026-06-15 from `docs/adr/0001-role-scoped-openapi-documents-v2-only.md`, which split the
> decision log into a second directory and collided with `docs/architecture/adr/0001`. Content unchanged
> except this note and the heading.

## Context

The pre-existing API published two OpenAPI documents — `User` and `Administration` — split by path
substring (`DocumentPathGroupFilter`). During the DDD migration we introduced RBAC-driven,
role-scoped documents (`User` / `ProviderAdmin` / `Admin`) generated by `RoleAccessDocumentFilter`,
which filters each document to the operations its audience can actually call through the Gateway.

Commit `cc8e4d5a` rolled that role split out **globally**: it set `options.ShouldInclude = _ => true`,
deleted `DocumentPathGroupFilter`, renamed `Administration` → `Admin`, and added `ProviderAdmin`. The
side effect was that every **legacy** endpoint was swept into the new role-scoped documents and the
original `User`/`Administration` document pair (with their public URLs) disappeared. The role split was
only ever intended for the **v2 / refactored** endpoints.

## Decision

Publish **five** documents in two generations that never mix:

- **Legacy (preserved verbatim):** `User`, `Administration` — `DocumentPathGroupFilter` (path-substring
  split), scoped to legacy endpoints via `ShouldInclude = !RelativePath.StartsWith("api/v2/")`.
- **v2 (audience-grouped):** `v2-User`, `v2-ProviderAdmin`, `v2-Admin` — scoped to refactored endpoints
  via `ShouldInclude = IsV2(api) && AudienceOf(api) == <document audience>`.

The generation discriminator is the **`api/v2/` route prefix** (every refactored endpoint is mapped under
`MapGroup("api/v2")`; no legacy endpoint is). Within v2, a document's membership is decided **statically** by
the endpoint's ApiExplorer `GroupName`, set with `.WithGroupName(ApiAudience.*)`; an untagged v2 endpoint
defaults to `v2-User`. The audience tag is derived from `roleManagmentRBAC.json` (the existing role→endpoint
source of truth) but baked into code, so document generation needs **no database and no auth**.

**Documentation is not authorization.** The v2 split is a *description* grouping only — it does not gate
access. RBAC is enforced by the Gateway **at call time**, independently of these documents. Accordingly
the OpenAPI/Scalar endpoints are `AllowAnonymous`: the full spec is always viewable, and the documents are
never empty just because RBAC data is missing or stale.

## Considered options

- **RBAC-driven document filtering at generation time** (`RoleAccessDocumentFilter`, the original form of
  this ADR). **Rejected and removed.** It coupled the docs to a live DB lookup of the RBAC store, so the
  v2 documents rendered empty whenever the seed (`roleManagmentRBAC.json`) had not been imported into the
  running DB — and it conflated documentation visibility with authorization. Enforcement belongs at call
  time, not at doc time.
- **Migrate all documents to RBAC at once** (the `cc8e4d5a` approach). Rejected: it broke the public
  `User`/`Administration` document URLs and applied a v2-only concept to legacy endpoints.
- **One combined v2 document.** Rejected: loses the per-role grouping the original requirement asked for.

## Consequences

- Document names are public URLs (`/scalar/{name}/openapi.json`); the parallel `User` + `v2-User` pair
  is intentional for the migration window. Legacy documents shrink to nothing as endpoints migrate to
  `v2/`, at which point the legacy pair (and `DocumentPathGroupFilter`) can be removed.
- A new v2 endpoint that should not live in `v2-User` must carry an explicit `.WithGroupName(ApiAudience.*)`;
  forgetting it places the endpoint in `v2-User` (visible, never hidden) rather than dropping it.
- The audience tags and the RBAC store are now two representations of the same role→endpoint intent. They
  can drift; the RBAC store remains the enforced source of truth, the tags are documentation only.

## Amendment 2026-09-30: the published set follows `V1Api`, and a `Service` document (T-USR-3-06, #330)

- The published set is `ApiDocuments.Published(isV1ApiEnabled)`. The legacy `User` and `Administration`
  pair is registered, offered in Scalar and read by the gateway only while `FeatureManagement:V1Api` is on.
  `Service` and the three v2 documents are published always.
- `Service` is an always-published, public document (`/api/Service/openapi.json`, anonymous like the
  others) of the **ungated legacy endpoints**: every `/api` route outside `/api/v2` that
  `MapV1CoreEndpoints` does not map, so it carries no `V1Api` flag metadata and is served whatever the flag
  says. Today that is RemI (`GET /api/remi/users`, `GET /api/remi/projects`), `GET /api/version`,
  `GET` and `POST /api/DataStaging/DataStagingLocations`, `GET /api/DataStaging/WorkerData`, and the
  HEAppE module's `/api/Heappe/*` (CommandTemplate, CommandTemplatePermissions, CommandTemplates,
  Partitions, ListChangedFilesForJob, ResourceAudit and KillSwitch), 20 operations. They leave `User` and
  `Administration` with their paths, schemas, `operationId`s and authorization unchanged. The document
  exposes no more than the public legacy pair exposed before.
- Selection is by endpoint metadata, so a future ungated route lands in `Service` by construction: the
  legacy pair takes `!IsV2` endpoints carrying an `EnabledByFeatureFlagMetadata` for `V1Api`, and `Service`
  takes `!IsV2` endpoints without one. `Service` registers `UnversionedHeappeTagDocumentTransformer` and
  no `DocumentPathGroupFilter`.
- `/api/Service/*` (the v1 `ServiceEndpoint` group) is `V1Api`-gated and stays in the legacy pair; it is
  not part of the `Service` document.
- The build pins `V1Api=true` while it generates the snapshots, so `API_user.json` and
  `API_administration.json` are still committed. `openapi_diff` and `lint_openapi` cover all three legacy
  generation files (`API_user.json`, `API_administration.json`, `API_service.json`).
- Acceptance: with `FeatureManagement:V1Api=false` on both hosts, the gateway answers `404 route.not_found` for
  `/api/Users`, Scalar offers only `Service` and the v2 documents, `/api/User/openapi.json` is 404 at the
  API and no longer public at the gateway (401 anonymous, 403 `auth.no_permission_mapping` authenticated),
  and RemI, `api/version`, `api/DataStaging/*` and `api/Heappe/*` keep answering as before.
