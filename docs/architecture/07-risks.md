# Risks

| id | risk | trigger | owner | status |
|---|---|---|---|---|
| R-01 | The retention of client IP addresses in the append-only audit archive (`SourceIp`) and in logs and request summaries is unset (`TODO(question)`, [ADR 0114](adr/0114-trusted-proxy-forwarded-headers.md)). | Both hosts apply forwarded headers from trusted proxies, so records carry real client IPs. | DPO | open |
| R-02 | The retention of `ClientIp`, `UserAgent` and non-credential query values (on the request summary and on Yarp/HttpClient events flushed by the pre-error buffer) is unset (`TODO(question)`, [ADR 0112](adr/0112-logging-modes.md)). | Every request writes one summary in every mode, the public token routes included (token segment redacted). | DPO | open |
| R-03 | With `TokenExchangeEnabled` off, the caller's broad token is forwarded through the NexusApi proxy `{TokenExchange:Nexus:BaseUrl}/api/heappe/{identifier}/` for any valid identifier ([ADR 0118](adr/0118-caller-token-is-exchanged-per-heappe-instance.md), [ADR 0119](adr/0119-nexusapi-settings-under-token-exchange-and-a-startup-gate.md)); userorg no longer checks `Enabled`, NexusApi answers 404 for unknown and disabled instances. An http `BaseUrl` carries that token, and with the flag on the NexusApi client secret, in cleartext: acceptable only on a network segment that is not shared, production uses https. Accepted, the flag is the kill switch for an IdP outage. | The flag is switched off, by default or to recover from an IdP outage. | Heappe module owner | accepted |
| R-04 | The introspection client also performs the token exchange ([ADR 0118](adr/0118-caller-token-is-exchanged-per-heappe-instance.md)): a leaked secret allows both, and rotating it restarts gateway and api. Keycloak grants it exchange permission per HEAppE client, never realm-wide. | A non-HEAppE audience needs the exchange, or the secret leaks or is rotated; a dedicated exchange client then replaces it. | Heappe module owner | open |
