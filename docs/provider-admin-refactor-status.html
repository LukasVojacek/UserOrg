Chování při ?noCache=true s N resources na sdílené instanci (Legacy bug)

Legacy groupuje po (URL, ResourceName). S noCache options (DisableLocalCacheRead + Write + DistributedCacheRead + Write) každá skupina volá GetCachedClustersForLocationsAsync přes vlastní Lazy<Task>. Lazy deduplikuje jen uvnitř jednoho volání (přes lokace téže skupiny), ne přes skupiny. Výsledek: 3 resources na URL_A + ?noCache=true → 3 samostatné HTTP fetche celého katalogu z URL_A. v2 problém nemá — groupuje po URL, je tedy vždy jen 1 Lazy, 1 fetch.

Škálování problému (legacy noCache): Počet redundantních HTTP katalog-fetchů = Σ resources per instance. Při 5 resources na jedné instanci → 5× fetch celého katalogu (může být stovky kB JSON) v jediném requestu.
