60s HARD LIMIT

Proxy vyhodí spojení po 60 sekundách — co se do toho musí vejít

Každý request na TemplatesInfo musí odpovědět do 60 s. Uvnitř každé skupiny (per instance) se operace provádějí postupně: nejdřív liveness probe, pak teprve data call. Ale všechny skupiny běží paralelně — celkový čas requestu je čas nejpomalejší skupiny, ne součet všech.

Časový budget na jednu skupinu (jednu HEAppE instanci):
⏱ Liveness probe (max 15 s)
📡 Data call — katalog clusterů (max 45 s)

CO SE CACHUJE

Cache vrstvy — co chrání opakované volání

Každý request prochází dvěma vrstvami cache. L1 hit = žádné HEAppE volání vůbec. L2 hit = žádný HTTP catalog fetch, ale liveness proby stále běží.

L1 — Projekt cache HIT → 0 ms, 0 HEAppE volání

Uloží celou složenou odpověď projektu (všechny resources, všechny clustery). TTL: 5 minut. Pokud je v cache → request vrátí data okamžitě bez jakéhokoliv kontaktu s HEAppE.

v1: TemplatesInfo_{shortName} (HybridCache)
v2: OutputCache per response URL + query
Uloží se jen při 100% úspěchu — při jakékoliv degradaci se neuloží

❌ Nevzniká při: změně projektu · invalidaci adminem · jakékoliv degradaci (mrtvá instance)

↓ při L1 miss
L2 — Instance cluster cache HIT → žádný HTTP, proby stále běží

Uloží data z HEAppE per instance. Liveness proby se vždy provádějí — L2 cache je jen pro katalog dat. Pokud probe projde a L2 hit → žádný HTTP catalog fetch. TTL: 5 minut.

v1 legacy — per cluster
Heappe_Cluster_URL_A_deucalion-cpu
Heappe_Cluster_URL_A_deucalion-gpu
Heappe_Cluster_URL_A_deucalion-fat
Heappe_Cluster_URL_B_barbora-cpu

Granulární — 1 entry per cluster. Umožňuje přesnou invalidaci po cluster-level změně.

v2 nová — per URL (celý katalog)
Heappe_Clusters_URL_A (celý katalog)
Heappe_Clusters_URL_B
Heappe_Clusters_URL_C
… 1 záznam per instance URL

Jednodušší — 1 entry per URL. Jeden fetch stačí pro všechny resources na té instanci.

L2 invalidátor: Změna command templates na instanci → Heappe_Clusters_{url} tag evicted → příští request re-fetchne katalog z dané instance.

Liveness probe není nikdy cachovaná — cíleně. Jde o levný GET (~100 ms pro živou instanci) který ověří, zda má smysl čekat 45 s na katalog. Bez probe by mrtvá instance mohla zdržet celý request o plných 45 s místo 15 s.
